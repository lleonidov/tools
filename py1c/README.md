# Тестовые обработки для Vanessa ADD

Каталог `py1c` содержит инструменты для подготовки тестов в формате внешних обработок 1С. Исходный тест хранится в одном файле BSL. Из него можно собрать обработку EPF без запуска 1С с сохранением структуры исходных каталогов.

Все команды ниже выполняются из корня проекта. Для создания шаблона нужен Python 3.

## addTestUnitEPF.py и addTestIntegrationEPF.py

Создают шаблоны unit- и integration-тестов соответственно. Тип теста задается именем скрипта. Базовый запуск:

```bash
python3 py1c/addTestUnitEPF.py МойТест
python3 py1c/addTestIntegrationEPF.py МойИнтеграционныйТест
```

Файлы будут созданы в `src/tests/unit/epf/` и `src/tests/integration/epf/` соответственно. Полный запуск с тегами и комментарием:

```bash
python3 py1c/addTestUnitEPF.py ПроверкаСложения --tags "smoke, arithmetic" --comment "Проверка сложения чисел"
python3 py1c/addTestIntegrationEPF.py ПроверкаОбмена --tags "integration" --comment "Проверка обмена"
```

Имя обязательно, параметры `--tags` и `--comment` необязательны. Чтобы увидеть справку, запустите нужный скрипт с `--help`. Правила имени и содержимое шаблона описаны ниже.

## addTestEPF.py

Создает BSL-шаблон теста для Vanessa ADD в `src/tests/<тип>/epf/<имя>.bsl`. Если каталог отсутствует, скрипт создаст его. Если файл уже существует, скрипт завершится с ошибкой и не перезапишет его.

Базовый запуск:

```bash
python3 py1c/addTestEPF.py МойТест
```

Будет создан файл `src/tests/integration/epf/МойТест.bsl`: по умолчанию используется тип `integration`.

Полный запуск:

```bash
python3 py1c/addTestEPF.py ПроверкаСложения unit "smoke, arithmetic" "Проверка сложения чисел"
```

Будет создан файл `src/tests/unit/epf/ПроверкаСложения.bsl`. Аргументы передаются по порядку:

```text
addTestEPF.py <Имя> [unit|integration] [Теги] [Комментарий]
```

- `Имя` - обязательное имя файла и часть имени тестовой процедуры. Допустимы русские и латинские буквы, цифры и подчеркивание; первый символ не может быть цифрой.
- `unit|integration` - тип теста; по умолчанию `integration`. Также принимается вариант `integretion`, который преобразуется в `integration`.
- `Теги` - необязательная строка, записывается в комментарий заголовка; по умолчанию пустая.
- `Комментарий` - необязательная строка для заголовка; по умолчанию пустая. Если комментарий нужен без тегов, передайте пустой аргумент `""` на месте тегов.

Шаблон содержит метаданные и идентификаторы обработки, процедуры `Инициализация` и `ЗаполнитьНаборТестов`, а также экспортную процедуру теста. Пример утверждения в ней закомментирован: после создания нужно написать проверки самостоятельно. Теги и комментарий записываются в файл как переданные строки.

## buildTestEPF.py

Собирает внешнюю обработку EPF из одного BSL-модуля без запуска 1С с помощью библиотеки `v8unpack`. Перед сборкой вызывает `prepareMetadataTestEPF.py`, который при необходимости дополняет заголовок исходного BSL. Второй параметр задает каталог результата или полный путь к файлу EPF. Для подготовки без сборки добавьте `--prepare-only`:

```bash
python3 py1c/buildTestEPF.py src/tests/unit/epf/МойТест.bsl build/test/unit/epf/
python3 py1c/buildTestEPF.py src/tests/unit/epf/МойТест.bsl build/test/unit/epf/МойТест.epf
```

## prepareMetadataTestEPF.py

Модуль для сборщика: функция `prepare_metadata` читает начальные комментарии BSL, проверяет идентификаторы и возвращает словарь параметров. Поля заголовка переносятся в начало исходного файла в заданном порядке. Для отсутствующих, некорректных и совпадающих идентификаторов создаются UUID; пустые синоним и версия заполняются именем файла и версией по умолчанию; другие комментарии и код сохраняются. `ClassId` возвращается с постоянным значением и не считывается из файла. При каждом запуске `ДатаИзменения` обновляется, остальные существующие значения сохраняются. Повторяющиеся поля заголовка вызывают ошибку. Кодировка UTF-8, BOM и переводы строк сохраняются. Модуль подключается из Python, отдельная команда запуска не предусмотрена.

## findBuildTestEFP.py

Ищет BSL-файлы непосредственно в каталогах `epf` внутри указанного каталога и запускает `buildTestEPF.py` для каждого. Поиск выполняется рекурсивно, но файлы во вложенных каталогах внутри `epf` собираются только тогда, когда их непосредственный родительский каталог тоже называется `epf`.

Базовый запуск из корня проекта:

```bash
.venv/bin/python py1c/findBuildTestEFP.py
```

По умолчанию тесты ищутся в `src/tests/`, подготовленные файлы сохраняются в `build/test/`, а готовые EPF - в `build/out/tests/`. Структура каталогов сохраняется относительно каталога поиска. Например:

- исходный файл: `src/tests/unit/epf/МойТест.bsl`;
- подготовленные файлы: `build/test/unit/epf/МойТест/src/`;
- готовая обработка: `build/out/tests/unit/epf/МойТест.epf`.

Все три каталога можно задать при запуске:

```bash
.venv/bin/python py1c/findBuildTestEFP.py путь/к/тестам --build-dir путь/к/подготовленным --output путь/к/epf
```

Для каждой обработки сначала запускается `buildTestEPF.py` с параметром `--prepare-only`. При успехе подготовленный каталог `src` собирается через `python -m v8unpack -B`. Библиотека `v8unpack` должна быть установлена в том же окружении Python. Исходный BSL при подготовке может быть изменен модулем `prepareMetadataTestEPF.py`.

Для справки используйте `--help`. Если подготовка или сборка одного файла завершилась ошибкой, скрипт продолжает обработку остальных и возвращает ненулевой код завершения. Если подходящие файлы не найдены, он сообщает об этом и завершается без ошибки.
